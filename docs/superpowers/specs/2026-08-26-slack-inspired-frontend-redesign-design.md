# LAN Chat 雾蓝工作台前端改版设计

**日期：** 2026-08-26
**状态：** 已确认视觉方向，待用户审阅规格
**范围：** `frontend/` 的 mode、connect、host、workspace、settings 和 bridge-error 页面

## 目标

将现有 React/WebEngine 前端改为受 Slack 信息层级启发的局域网聊天工作台：导航与会话清晰分层，消息阅读区保持明亮、紧凑和高对比。视觉采用用户确认的“雾蓝与石墨”方向，不使用 Slack 商标、字体、图标或文案。

本次只改 UI 结构与样式，不新增搜索、线程、账号、文件传输或任何网络能力；所有 ChatBridge 命令、路由状态、权限判断和本地数据边界保持不变。

## 已确认的视觉系统

| 类别 | 规则 |
| --- | --- |
| 主色 | 雾蓝 `#2D6176`；选中项使用较亮的 `#3A778C` |
| 导航表面 | 淡蓝灰 `#E5EEF3` / `#F0F6F8`，不使用紫色主导航 |
| 内容表面 | 白色 `#FFFFFF`；页面背景 `#F2F6F7` |
| 文本 | 石墨 `#1E2D33`；辅助文字 `#61737B` |
| 状态 | 成功 `#2E8B70`，注意 `#B87925`，错误 `#B64D40`；颜色外必须保留图标或文字 |
| 形状 | 输入框 6px、卡片/弹窗 12px、主次操作可用 999px 胶囊圆角 |
| 节奏 | 4/8/12/16/20/24px 间距；不引入新字体或新 UI 依赖 |

使用项目已有 `lucide-react` 图标和系统字体。当前的猫图资产可继续作为本项目素材，但不作为 Slack 风格标识。

## 页面设计

### Workspace

桌面使用四栏网格，不改变现有组件职责：

1. `WorkspaceRail`：52–68px 的淡蓝灰工具栏，保留品牌、页面切换、设置和移动端侧栏入口。
2. `ConversationSidebar`：约 220–248px 的浅蓝灰会话栏，依次呈现工作区名、搜索、频道、私聊、未读数与身份信息；活动会话用雾蓝实色和白字标明。
3. 中央聊天区：白色主阅读区。`ChatHeader` 使用一行会话标题/状态和紧凑动作；`MessageTimeline` 以列表而非厚重气泡为主；`MessageComposer` 固定在底部。
4. `MemberPanel`：约 210–240px 的白灰成员栏，仅显示当前会话成员、在线/管理状态和私聊入口。

窄窗口继续复用现有成员/会话弹窗入口，不新增 drawer 状态或新路由。消息、引用、撤回、复制、创建频道、管理员操作和未读逻辑均维持已有行为。

### 连接与建房

`mode`、远程连接、局域网发现和本地建房统一为居中的白色表单卡片：顶部 38–40px 图标块、明确标题与说明、输入标签、行内帮助/错误和右侧主操作。LAN 发现结果保持可点击列表，但以选中边框和说明文字传达状态，不能只靠颜色。

创建频道、成员管理、连接审批等继续使用 `ModalSurface`；modal 采用白底、12px 圆角、清晰标题行及右对齐操作，不改动现有表单字段、验证与确认流程。

### 设置与异常

`SettingsPage` 使用分组设置行：标题、辅助说明、当前值或开关位于同一行；用户可见的连接记忆和性能偏好不新增字段。`BridgeUnavailablePage` 与连接错误共用错误卡片：短说明、稳定错误文案和唯一的恢复主操作；不得展示密码、证书、私钥、数据库内容或原始异常堆栈。

## 组件与数据边界

实现只触及 `frontend/src/app/`、`frontend/src/components/` 和 `frontend/src/styles/global.css`；允许按现有 CSS 类添加少量语义 class，但不引入 Redux、组件库、Web API 或后端改动。

`App`、`WorkspacePage`、`SettingsPage`、`BridgeUnavailablePage`、`WorkspaceRail`、`ConversationSidebar`、`ChatHeader`、`MessageTimeline`、`MessageComposer`、`MemberPanel` 和 `ModalSurface` 保持现有 props 与 ChatBridge 调用方式。视觉令牌集中于 `global.css` 的 CSS 自定义属性；不建立新的主题切换机制。

React 状态、桥接 JSON、命令 envelope、密码处理、TLS、证书、SQLite、权限与消息路由完全不变。前端不得将密码、私钥、数据库或聊天内容写入日志、设计素材或测试快照以外的现有受控 fixture。

## 交互、响应式与可访问性

- 所有可点击元素保持可见焦点环；`button`、输入框、搜索和图标按钮均保留中文可访问名称。
- 主操作、禁用态、错误态、未读态和在线态必须有文字/图标/形状辅助，不能只依赖颜色。
- `prefers-reduced-motion` 继续禁用非必要动画；新增过渡仅使用 `opacity` 和 `transform`，时长不超过 160ms。
- 760px 以下隐藏静态会话栏和成员栏，复用既有 modal 入口；消息区、输入框、错误恢复操作保持可用。
- 消息正文、引用和长用户代码继续使用安全断行；不为消息列表或单条消息添加实时 blur。

## 验收与测试

1. 现有前端行为测试必须全部通过，桥接命令与 payload 不变。
2. 新增或更新组件测试覆盖：活动会话状态、连接/错误行内提示、设置行、消息输入禁用态、窄窗口的现有弹窗入口和关键 aria 标签。
3. `pnpm test -- --run` 与 `pnpm build` 通过；不新增 runtime 依赖。
4. 以已连接、断线、无消息、管理员和窄窗口状态手动检查：内容可读、焦点可见、错误可恢复、成员/会话入口可访问。
5. 运行 `scripts/build-modern.ps1 -Action Test`，确认前端产物仍可嵌入 Qt WebEngine 并且 CTest 通过。

## 不在范围内

- 新功能：线程、反应、文件上传、全局搜索、快捷切换器、通知中心、主题切换和移动端独立导航。
- 改变 ChatBridge、Go/C++ 协议、QML fallback、安装器、数据目录或权限模型。
- 使用 Slack 品牌资产、专有字体、图标、文案或容易造成混淆的整体标识。
