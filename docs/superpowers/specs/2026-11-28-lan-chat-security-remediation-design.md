# LAN Chat 安全修复设计

- 日期：2026-11-28
- 基线：公开仓库 `master`，提交 `7a68eafe64e12a56b818326c230e2737d4fa8a71`
- 状态：设计已批准，实施计划已编写
- 发布目标：合并到当前 `master` 的 1.4.1 版本线，通过候选分支评审后发布 `v1.4.1`；不升级到 1.4.2
- 目标：修复安全审查报告中的全部问题，同时保持现有协议、客户端功能和数据库读取兼容

## 1. 目标与非目标

### 1.1 目标

1. 消除未认证和已认证用户可触发的服务拒绝、资源耗尽和身份绑定绕过。
2. 保持旧客户端可用；新能力仅通过可选字段和能力协商启用。
3. 让发布资产可验证，并限制单次发布作业接触的密钥范围。
4. 让消息裁剪可恢复，备份可验证，服务可自愈和观测。
5. 清理公开运维信息，建立 GitHub 与生产环境的持续安全门禁。

### 1.2 非目标

1. 不改变“房主/在线服务器可见消息明文”的现有安全模型。
2. 不把 LAN UDP 广播本身不可认证视为缺陷；只修复无界资源累积。
3. 不改变 LAN“用户名 + 用户代码”的基本身份模型；只修复额外承诺的设备绑定竞态。
4. 不引入 Authenticode 签名，不改变更新器已有的最低版本策略。
5. 不在本轮重写 MLS 协议或改变附件对房主/服务器管理员的保密边界。

## 2. 兼容性不变量

1. 现有消息类型、字段含义和命令分发保持不变；不删除或重命名字段。
2. 新协议字段必须可省略、默认值为旧行为，并由能力协商限制使用范围。
3. 数据库迁移只增加表、列、索引和触发器；不执行破坏性降迁移。
4. 新配置项必须有兼容默认值；现有部署不修改配置时仍可启动。
5. 错误文案不得泄露账号是否存在、收件箱状态、文件路径或密钥信息。
6. 所有资源拒绝使用中性错误，不破坏客户端现有重连和错误处理语义。
7. 回滚使用迁移前备份或继续运行新版本，不通过旧版本直接读写已迁移库。

## 4. 服务端 P0 设计

### 4.1 LAN 准入控制

1. 新增独立于 `max_clients` 的预认证许可，分别覆盖 TLS 握手、登录帧和待审批连接。
2. 默认全局预认证 128、每来源 8；来源按 IPv4 和 IPv6 `/64` 规范化，方式与在线版一致。
3. 正式会话槽仅在房主批准后获取。待审批连接使用独立有界许可，不占用正式会话槽。
4. TLS 与登录帧读取分别计时，沿用在线版默认 5 秒和 8 秒；LAN 审批超时仍为 60 秒。
5. 认证失败、超时和断线必须通过 RAII 释放全部许可。
6. 新增 CLI 配置：`--lan-max-preauth`、`--lan-max-preauth-per-ip`、`--lan-tls-handshake-timeout-secs`、`--lan-login-frame-timeout-secs`。

### 4.2 Hub 锁与客户端移除

1. 任何 `deliver`、`system`、`room_system` 调用之后不得再次按 ID 直接索引 `clients`。
2. 移除成员时先刷新客户端目录，再发送通知；通知失败只记录结果，不继续访问已移除会话。
3. 所有 Hub 锁获取统一通过辅助函数；锁中毒时记录严重错误并恢复，但根因修复必须是消除 panic。
4. 增加发送队列满时执行 `remove_member`、删除房间、授予/撤销管理员等操作的回归测试。

### 4.3 设备绑定竞态

1. 审批通过后使用短锁事务读取当前 `device_secret_hash`。
2. bcrypt 哈希和验证必须在 Hub 锁外执行。
3. 当前哈希为空时，使用预计算哈希执行 `UPDATE ... WHERE device_secret_hash=''`；影响零行则重试。
4. 当前哈希非空时，先在锁外验证本次密钥，再在短事务中确认哈希未被其他连接改变；变化则重试。
5. 只有条件绑定成功或当前哈希验证成功，才返回 `device_bound=true` 并允许取走离线私信。
6. 两个并发审批即使均获房主批准，第二个不同设备也必须被拒绝。

### 4.4 Online 文件 IO

1. 文件命令拆成“授权/预留”和“IO/发布”两个阶段。
2. `Mutex<Online>` 内只执行短状态操作、SQLite 事务和元数据读取。
3. 哈希、`fsync`、文件读取和分块复制移动到独立有界阻塞池。
4. 每个文件使用独立锁和代次；IO 完成后在全局锁内复核授权、文件大小、修改时间和代次，再发布结果。
5. 首次下载计算摘要并缓存，缓存键包含文件 ID、大小、修改时间和代次；文件变化时重新校验。
6. `dm_file_get` 的首块请求不再无条件重新哈希整个文件。

### 4.5 群消息与数据库预算

1. 新增 `storage_usage` 字节账本，至少包含全局消息预算和每发送者群消息预算。
2. `chat_messages` 新增 `online_file_size`，文本、图片、文件统一纳入逻辑字节统计。
3. 插入、撤回、裁剪和归档时通过触发器或事务逻辑更新账本，保证幂等和可重算。
4. 写入前检查逻辑预算和物理磁盘高水位；超限返回中性错误，不删除旧消息腾出空间。
5. 群历史默认仍保留 10000 条，不新增默认 TTL；全局预算负责阻止无界增长。
6. 大库启动时不执行全表预算重建；提供后台有限批次校准和缺失索引自愈。

## 5. 配额与客户端设计

### 5.1 在线文件配额

1. `check_undelivered_quota` 的字节统计改为 `length(content) + online_image_size + online_file_size`。
2. 文件初始化时校验目标存在性和逻辑配额，提交时在同一 `IMMEDIATE` 事务内完成实际文件大小预留和幂等判断。
3. 全局文件预算从硬编码 2 GiB 改为 `--file-budget-bytes`，默认仍为 2 GiB；文件总数上限默认仍为 20000。
4. 配额拒绝时删除本次暂存记录和 `.partial` 文件，行为与现有文本/图片拒绝一致。

### 5.2 LAN 附件预留

1. 新增每用户未完成上传数量上限和预留字节上限，默认分别为 4 和 1 GiB。
2. `attachment.init` 在同一事务内检查用户上限和房间总配额。
3. 用户断线、离房、被移除或房间删除时异步释放其未完成预留。
4. 保留 24 小时过期和小时级清理兜底；新增更频繁的有限批次清理以缩短释放延迟。
5. 预留释放必须可重试，不能因附件 worker 重启而丢失。

### 5.3 房间目录

1. 新增能力 `lan-directory-page-v1`。
2. 请求复用现有 `limit` 和 `has_more`，仅新增可选 `rooms_offset` 字段；缺省为 0。
3. 新客户端每页最多 100 个房间；服务端在序列化入队前检查 64 KiB 帧上限。
4. 默认全局房间上限 200、每用户创建上限 50。
5. 旧客户端不声明能力时：目录可安全完整返回则保持原行为；超过安全大小时返回第一页并设置 `has_more`，不关闭连接。
6. 已有超量房间不自动删除，通过新客户端分页继续访问。

### 5.4 UDP 发现

1. 最多保留 128 个发现主机，主机名最长 64 个字符。
2. 每来源默认每秒最多接受 20 条合法公告，超限丢弃。
3. 使用证书 DER 计算稳定指纹，避免仅修改 PEM 注释/空白制造重复条目。
4. 整表状态发布至少间隔 100 ms；保留现有 6 秒未看到广播后的清理语义。
5. TLS 私钥校验和首次指纹确认流程不变。

### 5.5 Android

1. 新增不导出的 `NotificationRouteActivity`，通知 PendingIntent 显式指向该 Activity。
2. `MainActivity` 不再处理外部显式深链的 `lanchat://` data；只接受内部 trampoline 转交的路由。
3. 导航与标记已读分离，外部应用无法仅凭用户代码清除未读或群通知。
4. 切换账号分支先停用通知、清除账号绑定并注销/删除旧 FCM token，再清除旧会话；认证失败和显式退出保持现有清理路径。

## 6. 发布链设计

### 6.1 密钥隔离

1. 使用可复用工作流构建单个版别，`environment` 为 `release-lan` 或 `release-online`。
2. 每个 Environment 只配置通用名 `UPDATER_PRIVATE_KEY`、`UPDATER_PRIVATE_KEY_PASSWORD`，值分别为该版别密钥。
3. 单个签名步骤只接触当前版别的一份私钥和口令。
4. 两个 Environment 保留必需审批人；旧 `release` 环境在迁移完成后停用或移除签名机密。

### 6.2 签名与验证

1. 新增仓库内签名工具目录，锁定 `@tauri-apps/cli` 版本和 `package-lock.json`，使用 `npm ci` 安装。
2. 对安装器、便携 ZIP 和 `SHA256SUMS` 分别生成签名资产。
3. 上传前使用对应版别公钥验证全部签名，并验证版本、资产名、文件大小和签名中的版本。
4. 安装器内置公钥必须与签名验证公钥一致；不一致时工作流失败。
5. Android 构建后使用 `apksigner verify --print-certs` 比对预期证书 SHA-256。
6. 保留现有客户端更新验签和安装前再次验签逻辑。

### 6.3 CI 与供应链

1. 所有 GitHub Actions 固定到经核对的完整 commit SHA。
2. CI 增加 `cargo audit`、`pnpm audit --prod` 和 Gradle dependency verification。
3. 新增 Dependabot 配置，覆盖 Cargo、pnpm、GitHub Actions 和 Gradle。
4. Release 按 tag 设置 `concurrency.group`，`cancel-in-progress: false`。
5. 草稿创建前检查同 tag 草稿的 commit 和资产哈希；不存在则创建，存在且一致则复用，否则失败，不覆盖公开资产。

## 7. 历史归档、备份与恢复

### 7.1 历史归档

1. 新增 `message_archive` 表，保存被裁剪消息的完整字段、归档时间和原因。
2. 在线文件新增归档路径和归档时间；归档附件移入独立归档目录，不在活跃附件清理中删除。
3. 默认活跃历史仍为每会话 10000 条；归档默认保留 365 天，可通过配置调整。
4. 归档 TTL 到期后才允许物理删除归档消息和附件；删除操作有限批量执行。
5. 现有历史查询只读取活跃表，协议和 UI 行为不变。

### 7.2 备份工具

1. 新增 `lan-chat-backup` 工具，提供 `backup`、`verify`、`restore` 子命令。
2. `backup` 使用 SQLite 在线备份 API 生成一致快照，并复制 `.files`、可选 bot-key 和版本信息。
3. 备份清单包含每个文件的相对路径、大小和 SHA-256，使用后写原子方式发布。
4. `verify` 校验清单、数据库完整性和必需文件；`restore` 只允许恢复到不存在或已停止运行的实例。
5. LAN 主机提供 PowerShell 整目录备份脚本，覆盖证书、数据库及 sidecar、附件和设备密钥。
6. 备份与恢复文档明确加密、异地保存、保留周期和演练要求。

## 8. 服务化与可观测性

### 8.1 服务配置

1. 新增 `deploy/systemd/lan-chat-online.service`，包含 `DynamicUser`、`StateDirectory`、自动重启、资源限制和凭据加载。
2. 新增 Windows 服务安装脚本，使用系统服务管理器创建在线服务并配置失败恢复。
3. 服务默认使用最小文件权限，数据库、附件、bot-key 和 TLS 密钥不进入安装目录。

### 8.2 健康与指标

1. 新增默认关闭的 `--health-listen`，仅允许 loopback 地址。
2. `/healthz` 表示进程存活；`/readyz` 表示数据库、附件目录和维护任务可用。
3. `/metrics` 输出 Prometheus 文本，至少包含活跃/预认证连接、准入拒绝、锁等待、清理滞后、数据库/WAL 大小和磁盘余量。
4. 端点不包含聊天内容、账号、token、私钥或完整 IP。
5. systemd 和 Windows 服务配置启用健康检查与告警接入说明。

## 9. 公开信息与外部治理

1. 当前 `WORKLOG.md` 移除真实服务器地址、SSH 用户名、私钥路径、systemd 参数、在线用户 IP 和本机签名密钥路径。
2. 新增公开运维模板，只保留占位示例和操作步骤，不包含真实基础设施信息。
3. Git 历史重写只替换已确认的敏感字符串，覆盖所有 refs；执行前展示备份 bundle、命令和强推影响。
4. 轮换生产 SSH/部署凭据，限制 SSH 来源，检查并撤销不再需要的访问。
5. 启用 GitHub secret scanning 和 push protection。
6. 为公开 `master` 启用分支保护，要求全部 CI 检查通过，阻止强制推送和删除。
7. 生产部署先备份，再部署、健康检查、聊天/附件冒烟；失败按备份和上一版本回滚。

## 11. 错误处理与日志

1. 限流、预算不足、并发冲突和暂时不可用返回中性错误。
2. 客户端不会因新增资源错误清空已保存凭据。
3. 日志不包含密码、token、消息正文、私钥、完整证书私钥或敏感路径。
4. 指标使用聚合计数，不输出账号和完整来源 IP。
5. 附件 IO 失败时清理暂存和预留；数据库事务失败时回滚账本。
6. 归档、备份和恢复失败必须非零退出并保留原始数据。

## 12. 测试与验收

### 12.1 单元测试

1. LAN 预认证全局/每来源许可及 RAII 释放。
2. 设备绑定空哈希竞争、非空哈希竞争和哈希变化重试。
3. 发送队列满时移除成员不 panic、不锁中毒。
4. 文件字节账本、群预算和归档触发器的幂等与重算。
5. LAN 附件预留上限、断线/离房释放和 worker 重启恢复。
6. UDP 发现上限、DER 去重和状态发布节流。
7. 备份清单生成、校验和损坏检测。

### 12.2 服务端集成测试

1. 未认证连接占满预认证槽时，正式会话和审批仍可用。
2. 目标队列满时房主移除成员，服务持续可用。
3. 两个并发审批使用不同设备密钥，只有一个成功。
4. 大文件首块重复下载不重复全文哈希，且不全服阻塞。
5. 群消息达到全局/发送者预算后拒绝新写入，旧消息保留。
6. 32 MiB 文件计入收件人 64 MiB 配额。
7. LAN 用户无法通过声明大小锁死房间配额。
8. 新旧客户端房间目录请求均不因超大帧断线。
9. 带 WAL 的数据库与 `.files` 备份后恢复到临时实例并验证消息和附件。

### 12.3 客户端与 Android 测试

1. UDP 洪泛下发现列表不超过上限，UI 不无限增长。
2. 新客户端分页加载完整目录，旧客户端收到安全首页。

### 12.4 发布链测试

4. Android 证书指纹不匹配时发布失败。
5. 同一 tag 并发运行不产生重复草稿或资产覆盖。

## 13. 发布与回滚

1. 从当前 `master` 创建安全修复候选分支，按本规格顺序实施；候选分支保持版本号 1.4.1。
2. 全量门禁通过后创建 PR 并合并回 `master`，确认工作树、版本清单和迁移检查无误。
3. 服务端 P0 和配额修复随 1.4.1 一起发布，旧客户端继续可用；新客户端启用可选分页能力并保留降级路径。
4. 发布链改动在正式 `v1.4.1` 发布前使用测试 Environment 和测试密钥验证，不创建更改版本号的 RC tag。
5. 合并后在 `master` 创建并推送 `v1.4.1` 标签，触发 Release 工作流；审核签名资产后发布正式 Release。
6. 生产数据库迁移前执行一致性备份；迁移失败停止发布并使用备份恢复。
7. 不执行破坏性降迁移；旧二进制回滚只用于迁移前备份。
8. 外部 Git 历史重写、强推、凭据轮换和生产部署在展示具体命令与影响后分别确认。
