# 核心聊天闭环：第 1 阶段设计

## 目标

在不修改 Go TLS 服务端、帧协议或 C++ 网络工作线程的前提下，补齐 React 工作区的核心聊天交互：房间创建、成员私聊、引用预填、消息删除/撤回，以及命令反馈。

## 约束

- 保持既有链路：React -> QWebChannel -> ChatBridge -> GuiChatController -> GuiConnectionWorker -> Go Server。
- React 不直接处理 Socket、TLS、密码、证书、线程或数据库。
- 所有已登录用户可创建房间；创建者和管理员管理房间，其他成员只能加入、发消息和退出。
- `Remove` 仅隐藏当前客户端中的消息；`Recall` 向服务器请求撤回，仅对消息作者或管理员显示。
- `Quote` 只在输入框预填可编辑的引用文本，发送时仍为普通消息；本阶段不引入回复线程或协议字段。

## 前端交互

### 房间

房间栏新增“创建房间”入口和模态表单，包含房间名与公开/私密选择。提交 `room.create`，命令成功后刷新房间并选择新房间；失败时保留表单内容并显示错误。

### 私聊

成员列表中为非本地成员提供“发起私聊”。操作分发 `conversation.openPrivate`，控制器创建或激活相应私聊会话。不会向自己创建私聊。

### 消息操作

引用操作通过工作区级的 composer 草稿状态，将 `> 用户：原消息` 写入输入框。复制、删除本地消息和撤回保留既有命令。撤回入口按作者/管理员权限显示。

### 命令反馈

工作区维护最后一次命令的 pending/success/error 状态。命令执行中禁用相应提交按钮；失败提示清晰可见，输入内容和创建房间表单内容保留以便重试。

## 组件边界

- `WorkspacePage`：集中管理创建房间模态、引用草稿、命令反馈。
- `ConversationSidebar`：渲染创建房间入口和房间/私聊命令。
- `MemberPanel`：渲染发起私聊入口。
- `MessageComposer`：接收受控草稿、引用预填与发送状态。
- `MessageItem`：依据状态和权限显示可用消息操作。
- `ChatBridge` 与 C++ 控制器：复用已存在的命令，不新增网络接口。

## 验收与测试

1. 用户可创建公开或私密房间，成功后列表刷新并切换到该房间。
2. 用户可从成员列表向其他在线成员创建私聊，不能向自己创建。
3. Quote 能预填可编辑文本并通过普通消息发送。
4. Remove 仅移除本地可见消息；Recall 仅对作者或管理员显示并分发既有撤回命令。
5. 失败反馈可见，发送和创建房间的输入不会丢失。
6. 添加 React 组件测试并执行已有 C++ 桥接测试、前端构建与 Qt 资源一致性验证。
