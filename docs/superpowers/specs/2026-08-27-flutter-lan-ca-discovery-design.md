# Flutter 局域网主机与 CA 自动使用设计

## 目标

Flutter 原型提供“搜索局域网主机”入口。用户选择发现到的主机后，使用既有发现模块保存或复用的公开 CA 路径连接；手动连接其他服务器时仍使用用户填写的公共 CA 路径。

## 范围与边界

- Flutter 仅调度既有 `session.discoverLanHosts` 与 `session.connectDiscoveredHost` 命令，不实现新的网络发现或证书解析。
- 发现列表从现有桥接状态读取，显示主机的安全元数据和连接状态。
- 不扫描本机磁盘来猜测 CA 文件。
- 不读取、显示、复制、记录或上传私钥、证书内容、数据库、聊天和日志内容；Flutter 仅把既有发现模块管理的公开 CA 路径留在 C++ 核心内使用。
- 手动连接保留现有公共 CA 路径字段；不改变已有 QML、React、启动器、安装或发布流程。

## 流程

1. 用户点击“搜索局域网主机”。Flutter 发送 `session.discoverLanHosts`，事件轮询刷新状态。
2. UI 显示已有 bridge 状态中的发现主机列表。
3. 用户选择一个主机。Flutter 发送 `session.connectDiscoveredHost`，只提交 `hostId`、用户名和用户代码。
4. 既有 C++ 发现模块负责持久化并使用该主机对应的公开 CA；Flutter 不接触证书内容或路径。
5. 未发现主机、发现失败或连接失败时，显示 bridge 返回的安全错误文本。

## 测试与验收

- 先为发现与连接命令 payload、发现列表渲染、空列表和错误状态编写失败测试。
- Flutter 单测覆盖命令、选择和错误显示；不启动真实服务端。
- Windows Debug 构建继续通过。
- 人工验收：发现一台已有主机、选择后连接；手动远程连接仍可填写公共 CA 路径。
