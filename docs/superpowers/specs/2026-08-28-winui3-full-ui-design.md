# WinUI 3 全功能前端设计

## 目标

为 LAN Chat 新建原生 Windows 前端，以 WinUI 3 替代 Flutter 作为后续默认桌面 UI。新前端完整复用现有 `lan_chat_core.dll`、C++ `ChatBridge`/`GuiChatController`、TLS、局域网发现、CA 持久化和 Go 服务端，不修改通信协议或数据格式。

迁移期间 WinUI、Flutter 和 Qt 客户端并行存在。只有 WinUI 完成功能一致性和发布验收后，才允许修改默认启动入口。

## 技术与平台

- 新目录：`winui_client/`。
- 语言与框架：C#、.NET、WinUI 3、MVVM。
- 发布方式：非打包、独立运行目录，不要求 MSIX 安装。
- 系统范围：Windows 10 1809 及以上、Windows 11。
- Core 接入：C# 直接 P/Invoke 现有 C ABI，不增加 C++/WinRT 适配层或独立 Core 进程。
- 运行目录继续包含 `lan_chat_core.dll`、Qt 6、OpenSSL 和必要的 Windows App SDK/.NET 运行文件。
- 当前电脑缺少可用的 .NET SDK 和 WinUI 3 构建工具；实施第一阶段安装并验证所需组件，不改变现有 Flutter、Qt、Go 工具链。

## 视觉与布局

视觉采用 WinUI 原生 Fluent 交互和控件，使用 LAN Chat 现有石板紫作为品牌强调色。遵循系统明暗主题、文本缩放、键盘导航和高对比度设置；不复制 Flutter 自绘渲染路径。

应用分成两个主要状态：

1. 未连接时显示三张入口卡：远程服务器、创建本地主机、搜索局域网主机。
2. 连接后切换为三栏工作台：左侧会话列表、中间聊天内容、右侧成员与管理区。窗口变窄时右栏折叠为抽屉，再进一步收窄时左栏也折叠为导航面板。

设置、房间管理、本地主机文件路径选择使用 WinUI 对话框或独立页面。消息列表和成员列表使用支持虚拟化的原生列表控件。窗口缩放期间不运行自定义布局计时器、逐帧动画或 Core 刷新逻辑。

## 组件边界

### Views

- `ConnectionModePage`：三种连接模式入口。
- `RemoteConnectionPage`：服务器地址、端口、身份、CA 路径与 localhost TLS SNI。
- `LocalHostPage`：服务端程序、证书、私钥、数据库、身份选择。
- `LanDiscoveryPage`：搜索、空状态、错误状态、主机选择与身份输入。
- `WorkspacePage`：三栏自适应聊天工作台。
- `SettingsPage`：性能模式和连接日志设置。
- 管理对话框或抽屉：房间、成员和连接审批操作。

View 只负责布局、可访问性和用户输入，不直接调用 P/Invoke 或解析 Core JSON。

### ViewModels

- `ShellViewModel`：未连接/连接后的主导航状态。
- `ConnectionViewModel`：三种连接流程、输入校验和忙碌状态。
- `WorkspaceViewModel`：会话、消息、选中项和消息操作。
- `AdministrationViewModel`：房间、成员、审批和权限门控。
- `SettingsViewModel`：既有 Core 设置映射。

ViewModel 仅消费强类型状态并生成现有 JSON 命令。UI 会执行空值、端口范围、自操作和权限等即时校验，Core 继续作为最终权限与协议校验者。

### CoreInterop

- `LanChatCoreNative`：六个 C ABI 函数的精确 P/Invoke 声明。
- `LanChatCoreHandle`：基于 `SafeHandle` 的一次性句柄所有权。
- `NativeString` 边界：UTF-8 解码后始终调用 `lan_chat_core_free_string`。
- `CoreRuntime`：在一个专用后台线程上串行执行创建、命令、状态、事件和销毁。
- `CoreCommand` 与强类型状态模型：负责 JSON 序列化、反序列化和字段兼容。

禁止多个线程同时调用同一 Core 句柄。退出顺序固定为停止事件循环、拒绝新命令、清空正在执行的调用、销毁句柄。

## 数据流

1. `CoreRuntime` 在后台线程创建 Core，并读取一次初始状态快照。
2. 窗口激活时以 100ms 间隔清空事件队列；窗口未激活时暂停定时轮询，恢复时立即清空一次。
3. `result` 和 `error` 事件更新命令结果或错误提示；只有收到 `state` 事件时才重新读取完整状态快照。
4. JSON 在后台线程转换为不可变强类型状态，通过 `DispatcherQueue` 一次性应用到 ViewModel。
5. 用户操作生成 `winui-1`、`winui-2` 这类进程内递增 ID 的现有 Bridge 命令，经后台队列串行提交。

Core 仍是网络线程、TLS、证书持久化、服务端进程和聊天状态的唯一所有者。UI 不缓存或重新实现协议状态机。

## 功能一致性

WinUI 完成前必须覆盖 Flutter 当前已经接入的所有能力：

- 模式选择页。
- 远程服务器连接、CA 路径和 localhost TLS SNI。
- 本地主机创建与服务端程序、公开证书、私钥、数据库路径选择。
- 局域网搜索、空状态、错误状态、选择主机连接，以及 Core 管理的 CA 自动发现和复用。
- 房间、私聊、会话选择、消息发送。
- 消息复制、本地删除、撤回和失败重试。
- 用户目录与房间目录刷新。
- 房间创建、加入、离开、邀请、移除成员和删除。
- 普通成员从成员目录发起私聊。
- 管理员连接审批、拒绝、禁言和踢出；禁止管理员对自己执行成员操作。
- 性能模式和连接日志设置。
- 断线、连接中、失败、Core 加载失败和命令失败状态。

不得为了 WinUI 新增协议命令，也不得删除旧客户端仍使用的字段或行为。

## 错误与安全

- `lan_chat_core.dll` 缺失、导出不匹配、依赖 DLL 加载失败或 Core 创建失败时显示阻断式诊断页，包括实际查找路径和系统错误，不静默降级。
- 单次命令失败使用 WinUI `InfoBar` 显示 Core 返回信息，同时保留最后一份有效状态。
- 状态 JSON 解析失败时保留最后有效状态并报告错误；不得把损坏数据替换成虚假的空会话。
- 文件选择器只把路径传给 Core。UI 和测试不得读取、复制、输出、哈希或上传私钥、证书内容、数据库、聊天记录或日志内容。
- 不在注册表、设置文件或诊断输出中新增敏感内容持久化。

## 实施分解

这是完整迁移的总规格。以下每个阶段分别编写实施计划、独立构建和验收；前一阶段通过审查后才进入下一阶段。首份实施计划只覆盖阶段 1。

### 阶段 1：工具链、应用壳与 Core 接入

安装并验证 .NET/WinUI 3 构建环境；创建非打包 WinUI 应用、主题资源、P/Invoke、CoreRuntime、强类型状态和阻断式 DLL 诊断页。该阶段交付可启动、可读取真实 Core 初始状态的独立程序。

### 阶段 2：连接流程

完成三入口选择页、远程连接、本地主机和局域网发现；验证 CA 自动发现、TLS SNI 和路径传递行为与现有 Core 一致。

### 阶段 3：聊天工作台

完成三栏自适应布局、会话、消息、输入和消息级操作，并验证大量消息下的列表虚拟化与缩放流畅度。

### 阶段 4：管理与设置

完成成员、房间、连接审批、管理员操作、权限门控和设置。

### 阶段 5：完整验收与入口切换候选

执行功能对照、真实 Core 集成、运行库、Windows 10/11、性能和人工验收。该阶段通过后只生成“可切换默认入口”的候选，不自动删除 Flutter 或 Qt 客户端。

## 测试与验收

- P/Invoke 单元测试验证函数签名、UTF-8、空指针、字符串释放和 SafeHandle 一次释放。
- 使用可替换 `ILanChatCore` 的 ViewModel 测试验证每条命令 JSON、输入校验、权限门控和状态映射。
- JSON 契约测试使用现有 Core 快照和事件样例，验证未知字段兼容与必需字段失败。
- 真实 Core 受控集成测试验证创建、初始快照、命令、事件和销毁。
- Release 独立启动检查确认目标 Core、Qt 和 OpenSSL DLL 全部从程序目录加载，且缺失依赖时诊断准确。
- 功能对照表逐项验证本设计“功能一致性”章节中的能力。
- 自动缩放检查在 900×620 与 1380×860 之间执行 120 次、每次间隔 40ms：总耗时不得超过 8 秒，单次窗口尺寸调用 P95 不得超过 33ms。
- 用户连续拖动四条边和四个角，确认内容持续更新、输入可用，且不再出现 Flutter 约 9 FPS 的缩放表现。
- Windows 10 1809+ 与 Windows 11 分别至少完成一次 Release 启动、连接和聊天冒烟验证。

## 范围外事项

- 不修改 Go 服务端、网络协议、数据库架构或证书信任模型。
- 不重写 C++ Core 的网络和业务逻辑。
- 不在首轮迁移中引入 MSIX、自动更新、云同步或新聊天功能。
- 不删除 Flutter、Qt 或 React 代码。
- 不合并无效的 Flutter Skia 默认修复或 Flutter resize 诊断代码。

## 回退

WinUI 位于独立目录且默认入口保持不变。任何阶段失败时停止发布该目录即可，Flutter 和 Qt 客户端继续可用；不存在协议、数据库或用户数据迁移回退。
