# MLS 端到端加密实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏旧客户端的前提下，为私聊和聊天室提供 RFC 9420 MLS 端到端加密与可恢复的本地密钥备份。

**Architecture:** 服务端保留身份、成员和投递职责，只保存 MLS 公钥包、提交/welcome 与不透明密文。C++ 客户端持有 MLS 状态；每个私聊是二人 MLS 组，聊天室是同一 MLS 组。恢复包仅是用恢复口令加密后的客户端状态，服务端永不接触私钥或明文。

**Tech Stack:** Go、SQLite、C++17/Qt、OpenSSL 3、RFC 9420、MLS++（C++ RFC 实现，固定版本与校验和后引入）。

## Global Constraints

- 维持 4-byte big-endian UTF-8 JSON framing 和 64KiB 上限；MLS 二进制以 base64 置于可选字段中。
- 旧 `room_chat`、`private_chat`、历史、回执以及桥接 `{id,type,payload}` 不改变语义。
- 新字段全为可选；不支持 MLS 的客户端收到 `crypto_required`，不得静默降级为明文。
- 服务器不解密、不搜索、不记录明文、私钥或恢复口令。
- 仅采用 RFC 9420 实现；不得自实现 TreeKEM、AEAD、KDF 或签名算法。
