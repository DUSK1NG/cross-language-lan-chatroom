# P6 性能与大历史记录验收

## 已落实的边界

- React 消息时间线只保留一个 100 条的可见窗口；向上滚动时按页加载较早消息。
- `ChatListModel` 每个会话最多保留 1,000 行；非活跃会话模型采用有界缓存。
- 初始历史记录不播放逐条进场动画；新追加消息才允许动画。
- `requestAnimationFrame` 以 8 帧批次上报，忽略后台和无效帧间隔。
- 性能策略在 P95 超过 16.7 ms 时降低动画工作；发布构建不包含诊断 overlay。
- 基准门禁拒绝软件渲染、未启用硬件加速、低于 60 Hz 和电池节能模式，
  并拒绝工作集增长超过 15%、P95 超过 16.7 ms、单次场景中超过一次 33.3 ms 动画尖峰。

## 参考机采样流程

在 i9-14900HX、RTX 4060 Laptop、16 GB 内存和外接显示器的参考机上，
使用硬件加速的现代客户端执行以下固定轮次：

1. 预热后记录工作集和设置页显示的渲染 API、刷新率、P95/P99。
2. 保留 2,000 条消息后切换频道/私聊 10 次，接收 100 条消息，并从设置页返回聊天页 5 次。
3. 记录峰值工作集、P95/P99、超过 33.3 ms 的尖峰次数和显示器刷新率。

采样目标：工作集增长不超过 15%、P95 不超过 16.7 ms、每轮尖峰不超过一次，且设置页确认硬件加速与至少 60 Hz。

GamePP 只采集 `lan-chat-gui.exe` 主进程的 21.89 FPS 旧结果不作为本门槛
证据；Qt WebEngine 的实际网页绘制发生在独立的 `QtWebEngineProcess.exe` 中。
