# LAN Chat 架构

## 运行时链路

```text
React / TypeScript（WebView2）
        ↓ Tauri 2 invoke / event
桌面客户端（Rust：client-core）
        ↓ TLS TCP
服务端（Rust 单进程：局域网房主模式 / 在线服务器模式）
        ↓
SQLite（本机聊天数据或在线服务器数据）
```

React 负责界面和交互。Rust 客户端管理 TLS 连接、房主进程和会话状态，并在同一进程内完成 MLS 附件加密。发布版把 Vite 产物嵌入桌面程序。

桌面客户端使用系统 TLS，服务端使用 rustls，房主服务在独立进程运行。Android 客户端通过 JNI 使用 Rust 传输层连接在线服务。

## 协议与桥接边界

- 协议唯一权威为 `protocol-rust`（crate `lan-chat-protocol`）：帧为 4 字节大端长度 + UTF-8 JSON，长度上限 65536 字节。
- React 不直接访问 socket、TLS、私钥、子进程或 SQLite，只能通过 `frontend/src/bridge/` 的桥接接口收发状态与命令。
- React 通过 Tauri 的 `invoke` 提交命令，通过 `listen` 接收连接状态、命令结果和传输进度。

## 房主数据与首次启动

统一运行包由 `LANChat.exe` 启动。首次作为房主运行时，会在当前 Windows 用户目录生成证书、私钥和 SQLite 数据库：

```text
%LocalAppData%\DUSK1NG\LAN Chat\host\
```

房主的证书和数据库独立于安装目录。手动启动脚本也会读取旧安装路径下的证书和数据库。

LAN SQLite 的 `user_version=1` 建立历史搜索 FTS5 索引。`user_version=2` 迁移已有密码频道，并在 `lan_rooms` 中保存普通和私密频道、密码、白名单、管理员及 UUID 代次，`lan_mutes` 保存按用户代码设置的禁言。房间变更先写入数据库再更新内存。升级前应关闭房主并备份整个 `host` 目录，恢复时从同一份备份取回证书、数据库与附件。

LAN 服务端按连接、在线状态、审批和历史拆分 Hub。附件任务使用有界工作队列，在 Hub 锁外执行文件读写与校验。在发布或返回结果前校验当前会话与房间代次。暂存附件在数据库确认发布前不可下载，重启后可继续提交。

## 在线存储与迁移

Online SQLite 使用 FTS5 索引。`user_version=2` 增加磁盘附件元数据，`user_version=3` 增加群主、成员角色、邀请来源和历史访问边界。新图片和文件写入数据库旁的 `<数据库文件名>.files` 目录。数据库保存会话、长度、文件标识和摘要。已有 SQLite 附件可直接读取。

在停写的测试服务或数据库副本运行 `lan-chat-server --mode online --db OLD.db --migrate-storage --dry-run` 统计旧附件。移除 `--dry-run` 后写入并校验文件，保留旧负载以便验收。确认新旧客户端都能读取历史后，以 `--prune-legacy` 单独清理已验证的旧负载。恢复时使用同一时点的 SQLite、附件目录和原服务端版本。

## 成员连接审批

房主在本机首次连接时自动成为管理员。之后每位成员**每次建立连接**都会产生一个仅存于内存的连接请求：

1. 成员提交用户名、用户代码和 TLS 连接。
2. 在线房主在“连接审批”中核对身份并允许或拒绝。
3. 允许后，当前 TLS 连接立即进入聊天室；拒绝或 60 秒超时后连接结束。

批准不会写入数据库，也不会给某个设备永久通行权限。用户名和用户代码不是密码或公网账户凭据，房主应通过当面、电话或其他可信渠道核验身份。

## 网络与发现

- 局域网服务端默认监听 TCP `8888`，TLS 最低版本为 1.2（迁移不得降级）。
- 房主每秒通过 UDP `38888` 广播名称、地址、端口、公开证书和 SHA-256 指纹。
- 成员首次接受未知房主前必须人工核对证书指纹；IPv4 变化不会改变已确认的证书信任关系。
- UDP 广播本身不具备认证，发现到房间不等于确认了房主身份。

## 资源与安全边界

- 默认最多 64 个连接；登录和读写都有超时；每个连接的入站消息采用令牌桶限流。
- SQL 查询使用参数化语句；私钥不会经协议、发现广播或发布包传输。
- TLS 加密并验证客户端到房主的传输。房主服务端可以读取普通消息。客户端用 AES-256-GCM 加密附件，并用 `mls-rs` 保护附件清单。
- TCP `8888` 仅应在 Windows 防火墙的“专用网络”配置文件中开放，绝不能映射到公网。
- `server-lan.key`、`chat.db`、聊天记录和访问令牌必须留在房主本地受保护目录，不能加入 Git、同步盘或 Release。
