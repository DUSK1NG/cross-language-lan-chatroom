# LAN Chat 架构

## 运行时结构

```text
React 前端（Qt WebEngine）
        │ QWebChannel
ChatBridge / GuiChatController（C++）
        │ TLS TCP
Go Server（聊天室、消息与成员状态）
        │
SQLite（房主本机聊天数据）
```

React 只负责界面与交互；连接、TLS 校验、本地进程和业务状态保留在 C++ 层。发布版把已构建的前端作为 Qt 资源打包，Vite 只用于开发构建。

## 本地主机与数据位置

统一包由 `LANChat.exe` 启动。包含本地 Go Server 的运行包首次作为房主启动时，会生成证书、私钥和 SQLite 数据库；新数据固定保存在当前用户：

```text
%LocalAppData%\DUSK1NG\LAN Chat\host\
```

这样安装目录升级、便携包移动或卸载不会意外删除房主身份。为兼容旧版本，安装目录 `server-go\certs` 与 `server-go\chat.db` 中已经存在的数据会继续使用，但不会被自动移动。

成员端为每个“当前 Windows 用户 + 房主证书”生成一枚随机设备凭据，保存到：

```text
%LocalAppData%\DUSK1NG\LAN Chat\devices\
```

该凭据使用 Windows DPAPI 加密，React/WebEngine 与日志都拿不到原文；服务端只保存该凭据的 SHA-256 摘要。

## 网络与发现

- Go Server 默认监听 TCP `8888`，TLS 最低版本为 1.2。
- 房主每秒在 UDP `38888` 广播房间名称、地址、端口、公开证书和 SHA-256 指纹。
- 客户端首次接受未知房主前必须人工核对指纹；已知房主固定校验证书，IPv4 地址变化不改变信任关系。
- UDP 广播本身没有认证，不应把“发现到房间”视为身份保证。

## 服务端防护

- 连接数默认上限为 64，可由 `-max-clients` 调整。
- 登录、读写都设置截止时间，避免半开连接长期占用资源。
- 每个连接的入站消息使用令牌桶限流（每秒 8 条、突发 16 条）。
- SQL 查询使用参数化语句；TLS 私钥不会经协议、发现广播或发布包传递。
- 房主在本机回环地址首次连接时获得管理员设备授权；其他新设备只会创建待审批请求，在线管理员批准后才能建立会话。审批结果会同步给所有在线管理员。

## 安全边界

LAN Chat 是可信局域网工具。TLS 保护客户端与房主之间的传输，但服务端仍可读取消息，系统不提供端到端加密。用户名和用户代码只是显示/路由标识；实际接入依赖于按房主证书隔离、由 DPAPI 保护的设备凭据。房主创建后，其他设备必须由管理员在“设备审批”中确认。该审批降低局域网内的冒用风险，但不等同于跨公网账户认证。

TCP `8888` 只能允许 Windows 防火墙的专用网络配置文件，不得映射至公网。`server-lan.key`、`chat.db`、聊天记录和访问令牌必须保留在房主的本地受保护目录，不能加入 Git、同步盘或 Release。
