# TCP 隧道跨网络连接

本指南适用于 Sakura Frp 等支持 TCP 转发的外部隧道服务。隧道客户端、账号、令牌和服务商配置完全由房主管理；LAN Chat 只使用隧道公开的主机与端口建立 TLS 聊天连接。

## 房主配置

1. 在房主电脑安装并登录服务商提供的隧道客户端，例如 `frpc`。
2. 在服务商控制台创建 TCP 隧道。隧道的本地目标必须是 `127.0.0.1:8888`，不要直接转发到不受控的内网地址。
3. 启动 LAN Chat，选择“创建本地聊天室”，让它生成并持有本机的 `server-lan.crt`、`server-lan.key` 与 `chat.db`。
4. 启动外部隧道客户端，并向成员提供：隧道的公网主机名（或 IP）、映射端口，以及公开证书 `server-lan.crt`。
5. 保持 LAN Chat 打开；当成员请求出现时，在“连接审批”中核对名称和用户代码后点击允许。

`server-lan.key`、`chat.db`、隧道令牌、`frpc` 配置文件和服务商账号均只应留在房主一侧，不能发给成员、写入 LAN Chat 表单或提交到 GitHub。

## 成员加入

1. 在 LAN Chat 首页选择“通过 TCP 隧道加入”。
2. 填写房主提供的隧道主机与端口、自己的用户名和用户代码，并选择房主提供的 `server-lan.crt`。
3. 通过可信渠道核对房主身份和证书指纹后点击连接。
4. 等待房主审批；审批通过后会在当前连接中直接进入聊天室。

## 安全与排障

- 在隧道服务商侧启用账号保护、访问控制或 IP 白名单（若服务商支持）。
- Windows 防火墙只允许房主所需的网络范围；隧道目标为 `127.0.0.1:8888` 时，聊天服务无需直接暴露本机局域网端口给公网。
- `server-lan.crt` 是公开证书，可以分发；`server-lan.key` 是私钥，绝不可分发。
- TLS 会加密客户端到聊天服务端的连接，但聊天内容在房主服务端可见；这不是端到端加密。
- 隧道显示在线但无法加入时，先确认 LAN Chat 房主正在运行，再检查外部隧道客户端的本地目标是否仍为 `127.0.0.1:8888`，最后核对成员使用的主机、端口和公开证书是否来自同一房主。
