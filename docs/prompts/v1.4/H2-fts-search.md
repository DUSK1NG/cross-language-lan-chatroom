# H2 执行版：历史搜索与索引迁移

H1 通过后执行。先固定 `Store::history` 的既有分页和可读范围，再引入 FTS5 trigram。读 `server-rust/src/store.rs`、LAN 历史读取及在线编辑实现。

## 实施要求

1. **先建立回归场景。**用旧库夹具确认当前中文子串、1–2 字查询、标题栏中带引号和符号的字面查询、房间与私信/群隔离、倒序分页及游标。补充撤回、编辑、删除与历史裁剪的预期结果。按用例覆盖首次启动、第二次启动、迁移中断、只读连接以及后续版本索引损坏修复。
2. **版本与迁移。**在写库初始化的事务内完成既有 `message_id` 兼容重建、外部内容索引和触发器安装。LAN 与在线分别从 0 迁到 1。完整事务成功后推进版本。已有库缺失派生索引或触发器时只重建索引对象，保留既有 `user_version`，包括后续 S2–S4 的值。表重建会影响索引时在同一写事务内恢复，`lan_reader` 保持只读。
3. **索引。**`chat_messages_fts` 使用 `content='chat_messages'`、`content_rowid='id'` 和 `tokenize='trigram case_sensitive 1'`，通过插入、更新、删除触发器同步。建立后从原表回填，保留现有范围索引。撤回内容从搜索结果中排除，普通历史仍沿用现有撤回展示。
4. **查询。**按现有规则 trim。三个及以上 Unicode 字符用 MATCH 参数绑定，按字面短语转义引号。较短查询用 `instr`。只在明确可归类的 FTS 查询可用性错误时用等价 `instr` 并记录诊断，其他数据库错误按原路径返回。范围过滤、排序、上限、游标与 `has_more` 继续用主表语义。
5. **部署与恢复。**用旧库副本测启动耗时、索引占用和原消息行数，说明迁移期间的可用性。整体回退使用迁移前快照。若只修复或重建 FTS，事务内操作派生对象并维持数据库版本，按现有架构、协议和测试文档记录步骤。

## 验收

```powershell
cargo test --locked -p lan-chat-server
cargo test --locked -p lan-chat-server --test lan_desktop
cargo clippy --locked -p lan-chat-server --all-targets -- -D warnings
```

在 LAN 客户端完成「搜索两字中文 → 搜索长词和标点 → 翻页 → 撤回后再搜」。在线覆盖私信编辑、群范围及分页。用真实旧库脱敏副本或等价夹具验证搜索和重启，向后续阶段提供一次迁移、索引自愈和保留高版本三类证据。
