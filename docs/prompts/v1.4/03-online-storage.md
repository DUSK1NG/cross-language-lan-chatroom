# S3 执行版：在线附件落盘与历史迁移

H2 通过后执行。S4 复用本阶段的附件读写和权限接口。先读 `server-rust/src/store.rs`、`server-rust/src/online/transfer.rs`、桌面和 Android 私信附件收发及离线历史路径。

## 实施要求

1. **存储与发布。**在线库迁移到 `user_version=2`。数据库保留附件 ID、会话归属、路径、长度与摘要等元数据。用不可变附件 ID 命名文件，临时文件与正式文件放同一卷。分块写入和按需读取，验证长度及 SHA-256。文件发布完成后再事务性标记可读。记录可恢复的中间状态，重启后能识别未完成上传和孤立文件。取消、过期与空间不足反馈明确结果。
2. **兼容读写。**先支持「新文件落盘、旧 BLOB 仍可读」，覆盖 `online_file_chunks` 和 `chat_messages.online_image`。历史和离线消息继续提供可用的附件元数据。旧版在原上限内收发不变。保持会话和身份授权，覆盖私信发件人、收件人和第三方账户。
3. **迁移命令。**由 `lan-chat-server --migrate-storage` 执行，提供只读 `--dry-run`。演练时记录条目、空间需求、失败项与可继续的位置。实际迁移在经批准的维护窗口停写，先备份一致的数据库和文件目录。逐条写文件并校验，再原子切换记录。遇失败保留 BLOB，重跑时核对已完成的记录。迁移验收和恢复演练通过后才清理已迁条目的 BLOB，兼容读路径保留到旧数据清理完成。
4. **限额。**默认保证图片 4 MiB、文件 32 MiB。在桌面、Android、服务端统一发送和接收校验后再验收 10/128 MiB。启用新增能力前须定义旧版收件人、离线收件人以及同账号不同设备的行为。适用上限在选文件时可见。无法保证所有相关端可正常处理历史和离线交付时，本版沿用 4/32 MiB，存储迁移照常交付。
5. **回滚。**记录同一时点的数据库与附件文件快照、恢复顺序和切回旧程序的适用条件。切换后若已接收新消息，回滚前先明确保留方式与影响范围。用测试服务器完成停写、恢复和重新开放流程后再申请正式迁移。

## 验收

```powershell
cargo test --locked -p lan-chat-server -p lan-chat-client-core -p lan-chat-protocol
cargo clippy --locked -p lan-chat-server --all-targets -- -D warnings
```

用旧库副本覆盖 dry-run、迁移中断后重跑、重复执行、迁移后重启、老文件和老图片下载、迁移后新上传、过期/取消与整套恢复。一并验证私信原上限、会话隔离和两个方向的跨版本收发。记录迁移耗时、磁盘空间、兼容性和提额是否纳入 S5。
