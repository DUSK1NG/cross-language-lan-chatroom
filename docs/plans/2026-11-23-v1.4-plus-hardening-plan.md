## 3. 明确不做

- 局域网消息正文 E2EE（MLS 正文扩展）、设备信任免重复审批（进 1.5）。
- 在线私信 E2EE、推送通道抽象、可观测性（健康检查/指标/审计）。
- Google Play 上架、macOS/Linux 桌面端、两版服务端合并、代码签名证书采购。
- `socket2` / TCP keepalive（除非 H1 决策改为做）。
- 加固计划 §11「待评估」中的内容（删旧索引、搜索大小写、在线 BLOB 锁、附件线程池等）。
- 合并版不重写发布脚本，不改协议帧格式，不改前端与桥接边界。

## 4. 硬约束与不变量

1. **数据兼容**：`%LocalAppData%\DUSK1NG\LAN Chat\host\`（证书、chat.db）与 `LAN Chat Online` 数据必须能被新版本直接打开；表结构迁移走 `PRAGMA user_version`，幂等、可回滚；测试只用临时目录。
2. **协议不破坏**：4 字节大端长度 + UTF-8 JSON、单帧 1 ≤ length ≤ 65536 不变；新命令与限额靠 capability 通告，旧客户端行为逐字不变。
3. **局域网版零服务器**：不引入云账号、云存储、外部数据库；离线可开房可用。
4. **依赖**：不新增第三方依赖（含 dev-dependency）；存储用标准库与现有 `rusqlite` / `ureq` 体系；前端不新增 UI 框架。
5. **测试即验收**：每个任务附可执行验收命令；没有自动化测试的功能不算完成（手工验收单独列出）。跑不通的测试不得注释或 `#[ignore]`。
6. **安全不变量**：不关闭或放宽 TLS 证书/主机名校验；不新增绕过房主实时审批的路径；附件权限（房间/作者/过期）不得削弱；服务端不得获得附件明文；私钥、`chat.db`、日志、聊天内容不进 Git / Release / ZIP / 安装器 / 日志输出。
7. **Git**：仓库当前在分支 `feat/01-stability-downloads`，HEAD `78552a7`，约 305 项未提交改动（Rust 迁移整体未提交）。S0 提交基线前不得 `git reset` / `git clean` / `git stash` / `git checkout -- .` / 切分支；提交由用户在 G0 拍板。提交基线后：每阶段一个 `stage/*` 分支，验收后合并。
8. **环境**：本机默认 target 构建会因 MSVC `cl.exe` D8050 失败；允许用 `CARGO_TARGET_DIR=C:/lc-target` + `CARGO_PROFILE_DEV_DEBUG=0` 绕过，但报告必须同时贴原始失败与绕过结果；不得改 ACL/系统配置。
9. **前端边界**：React 不碰 socket、TLS、证书、私钥、SQLite；桥接集中在 `frontend/src/bridge/chatBridge.ts` 与 `frontend/src/app/runtimeBridge.ts`；动画只用短时 transform/opacity；性能面板不进发布 UI。
10. **仓库卫生**：根目录新增的第三方工具目录 `Claude-BugHunter/` 未被忽略，G0 时确认移出或加入 `.gitignore`；`out/`、`release/`、`target/`、`.tools/`、证书、db、日志不入库。

## 7. 工作流

- **Git**：S0 在用户批准后提交基线（tag `baseline-2026-11-23`），从该提交建 `main`；每阶段从 `main` 拉 `stage/N-name` 分支，验收通过后合并；每周五打 `v1.4.0-rc.N` 演练标签。
- **每阶段三步**：先写半页 design note（放 `docs/plans/design/`），再实现，最后跑门禁并更新文档。
- **提交**：小步提交，message 说明“为什么”；不提交密钥、db、日志、`out/`、`release/`、`target/`。
- **Agent 协作**：一次只给一份阶段 prompt；agent 按 §12 报告，人工验收通过再进下一阶段。H 阶段细节以加固计划 v2 为准。
- **交接**：每阶段结束在 `WORKLOG.md` 顶部追加一条（时间/执行者/改动/验证/下一步/阻塞）。

- S1-2 Tauri updater：`tauri-plugin-updater`；minisign 密钥（公钥进 `tauri.conf.json`、私钥进 GitHub Secrets）；两版独立通道（`latest-lan.json` / `latest-online.json`）；提示/进度/确认；局域网开房时提示“重启会断开所有成员”。
- S1-3 设置页“检查更新”；启动静默检查（失败静默）；显示版本与日期。
- S1-4 `scripts/make-updater-manifest.mjs`。
- S1-5 发布文档：`release-runbook.md`、`release-checklist.md`、`github-publishing.md`。

### S2：局域网权限持久化（5 人日）

- S2-1 数据表（LAN 库，`user_version` 从 **2** 开始）：`lan_rooms`、`lan_room_members`、`lan_room_admins`、`lan_room_mutes`。
- S2-2 启动加载：`Hub` 从库重建 `rooms`；`lobby` 虚拟不落库；`generation` 持久化单调递增。
- S2-3 写路径：建房/踢人/删除/密码/管理员/禁言同事务写库；DB 为真源。
- S2-4 安全语义：连接批准**不落库**、重启后仍需逐次批准；白名单只决定“批准后能进哪个房间”；加回归测试。
- S2-5 测试：“同一 db 启动两次 Hub”集成测试 + `lan/store.rs` 单测 + 扩展 `lan_desktop.rs`。

### S3：在线存储重构（6 人日）

- S3-1 `store::files` 模块；数据目录 `files/`；`online_files` 增 `path/hash/checksum`，内容不再进 BLOB；Online 库 `user_version=2`。
- S3-2 分块写盘：临时文件 → 校验长度与 SHA-256 → 原子 rename；读取按需分块；过期清理任务。
- S3-3 迁移命令 `lan-chat-server --migrate-storage [--dry-run]`：`online_file_chunks` 与 `chat_messages.online_image` → 落盘 → 校验 → 置 NULL/删表；迁移前 `PRAGMA integrity_check` 与 db 备份；幂等、逐条日志与统计。
- S3-4 限额与能力：图片 4 → 10 MiB、文件 32 → 128 MiB；capability `online-files-v2`，旧客户端仍按 32 MiB；协议文档同步。
- S3-5 测试：迁移夹具覆盖 dry-run 与实跑；上传/下载/取消/过期清理。
- S3-6 若 H4 启用了 WAL：迁移与备份文档说明 `-wal` / `-shm` 处理。

### S4：在线群能力（8 人日）

- S4-1 表结构：`online_groups` 增 `owner, announcement, avatar, created_at`；`online_group_members` 增 `role, joined_at`；Online 库 `user_version=3`。
- S4-2 命令与权限矩阵：`group_invite / group_kick / group_role / group_transfer / group_update / group_announce`；角色 `owner/admin/member`；表驱动测试。
- S4-3 群文件与群图片：复用 transfer 分块通道；仅成员可上传/下载；消息带附件元数据，历史可分页。
- S4-4 客户端 UI：群详情面板、成员列表、角色操作、公告编辑、群设置、群文件列表、图片预览；权限不足按钮置灰并提示。
- S4-5 事件与推送：群事件广播 `groups_changed`；群消息沿用 FCM，文案区分私信/群聊。
- S4-6 测试：权限矩阵单测；群文件 E2E；旧客户端收到未知命令忽略不崩溃。

### S5：Android、验收与发版（5 人日）

- S5-1 Android 0.4.0：接入单一版本源（versionName 0.4.0 / versionCode 16）；修 FCM 登录与消息收发稳定性；APK 随 Release 分发（不做应用内自动安装）。
- S5-2 文档同步：`docs/release-notes/v1.4.0.md`、`architecture.md`、`protocol.md`、`testing.md`、`release-acceptance.md`、`installer.md`、`unified-package.md`、`docs/README.md`。
- S5-3 验收：虚拟机双机（发现、审批、断线重连、房间持久化跨重启）；Android 真机（在线群、群文件、推送）；测试服务器（部署、存储迁移演练、群权限走查）。
- S5-4 发版：走 `release.yml` 出 1.4.0 全部产物；核对 SHA256 与 manifest；发布说明；回滚预案（上一版安装包 + 数据备份）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 8 周排期偏紧 | 延期或质量下降 | 每周 rc 演练；砍线规则前置（§6）；S3/S4 允许跨周 |
| 基线 e2e 已失败 | 后续门禁失真 | S0 必须先修绿或上报阻塞；不得忽略 |
| 本机 MSVC D8050 | 无法构建/测试 | 环境变量绕过 + 记录；全量门禁交 CI |
| 现有仓库 305 项未提交改动 | 误删/覆盖 | G0 先提交基线；S0 前禁 reset/clean/checkout；备份 `out/`、`release/` |
| 未跟踪的 `Claude-BugHunter/` | 进入仓库/提交 | G0 决定移出或加忽略 |
| 存储迁移损坏数据 | 在线文件丢失 | dry-run + 备份 + 校验 + 幂等；允许短时停机 |
| FTS 迁移耗时/体积 | 启动变慢、磁盘翻倍 | 迁移成本记录；大库提示；失败回滚不损坏 |
| 协议变更破坏旧客户端 | 老用户连不上 | capability 通告；旧命令保持；未知命令忽略 |
| 心跳超时误杀慢客户端 | 频繁掉线 | 20s/60s 固定关系；服务端不提供 >60 的上限；测试覆盖未协商客户端 |
| 附件并发写冲突 | 上传/聊天失败 | H4 决策 WAL 或 busy 重试 + 并发测试 |
| 无代码签名证书 | SmartScreen 警告 | 接受并写进发布说明；updater 完整性签名不能省 |
| 局域网持久化改安全语义 | 审批被绕过 | 审批不落库 + 回归测试；白名单只影响房间准入 |
| 群文件滥用 | 磁盘占满 | 每群配额 + 清理任务（P2 拍板数值） |
| Android CI 慢/NDK 漂移 | CI 超时 | 固定 NDK 版本、缓存、作业独立 |

## 12. 报告格式（每阶段结束、遇到决策门时）

1. 阶段/任务编号；2. 改动摘要（为什么）；3. 文件与行数变化；4. 协议/数据变更（capability、消息类型、表/触发器、`user_version` 按库列出）；5. 门禁命令与结果（本机 `-p` 范围 + 全量；失败贴关键输出）；6. 新增测试名；7. 环境阻塞与未验证项（D8050、桌面构建、手工验收）；8. 基线对照（`lan_desktop`、characterization 测试数）；9. 迁移成本（行数/耗时/DB 体积，B/S3/S4 阶段）；10. `Cargo.lock` 是否变化及原因；11. 需要拍板的问题。

完成后把任务清单 `- [ ]` 改 `- [x]`，下一行追加 `> 证据：<命令 + 结果 + 测试名>`。
