# v1.4 升级计划：局域网版 + 在线版

> 状态：待启动 · 制定于 2026-11-22 · 目标发版 2027-01-03
> 已被取代（2026-11-23）：执行以 [v1.4 升级与加固合并计划](2026-11-23-v1.4-plus-hardening-plan.md) 为准；本文保留原范围与决策记录。
> 版本：桌面两版 ```1.4.0```，Android ```0.4.0```（同一版本源派生）
> 执行方式：混合 —— 范围与关键决策由人拍板；实现、测试、文档由编码 agent 在独立分支完成
> 配套执行 Prompt：[docs/prompts/v1.4/](../prompts/v1.4/README.md)

## 1. 本版目标

| 编号 | 目标 | 完成判据 |
| --- | --- | --- |
| G1 | 发布与自更新 | 打 ```v*``` tag 一次产出 LAN/Online 各「ZIP + 安装器」共 4 个桌面产物与 APK；客户端内置检查更新并可自动下载安装 |
| G2 | 局域网版权限持久化 | 房间结构、私密/密码、成员白名单、管理员、禁言写入 SQLite；房主重启后仍在；连接批准仍逐次实时 |
| G3 | 在线版存储重构 | 文件与图片从 SQLite BLOB 迁到本地目录，DB 只留元数据；存量一次性迁移；限额提升 |
| G4 | 在线版群能力 | 邀请/踢人、管理员与群主转让、群公告与设置（名称/头像）、群文件与群图片 |
| G5 | 质量与交付底座 | Git 基线、单一版本源、CI 补齐（Android/安装器/TLS 验收/缓存）、文档同步 |

## 2. 本版明确不做

- 局域网消息正文 E2EE（MLS 正文扩展）——留到 1.5，见第 10 节。
- 「已批准设备免重复审批」的设备信任机制。
- 在线私信 E2EE、服务端推送抽象（FCM 之外的通道）、可观测性（健康检查/指标/审计）。
- Google Play 上架、macOS/Linux 桌面端、两版服务端合并。
- 代码签名证书采购（本版只保证 updater 自身的完整性签名）。

## 3. 硬约束与不变量

1. **数据兼容**：升级不得破坏既有数据目录 ```%LocalAppData%\DUSK1NG\LAN Chat\host\```（证书、chat.db）与 ```LAN Chat Online``` 数据；迁移必须幂等、可回滚。
2. **协议不破坏**：4 字节大端长度 + UTF-8 JSON、单帧 ≤ 64 KiB 不变；新命令与限额通过 capability 通告，旧客户端继续可用。
3. **局域网版零服务器**：不引入云账号、云存储、外部数据库；离线可开房可用。
4. **不引入重量级依赖**：不新增外部数据库/消息队列/前端框架；存储落盘用标准库与现有 rusqlite/ureq 体系；前端不新增 UI 框架。
5. **测试即验收**：每个任务附带可执行验收命令；没有自动化测试的功能不算完成（手工验收项单独列出）。
6. **手工验收受限**：本机只有一台 Windows，局域网双机验收用虚拟机补第二实例；在线版用测试服务器；Android 用真机。
7. **质量门禁**：合并前通过 ```cargo test --workspace --locked```、```cargo clippy --workspace --all-targets --locked -- -D warnings```、前端 ```lint/test/build```。

## 5. 工作流

- **Git**：S0 建基线后，每阶段从 ```main``` 拉 ```stage/N-name``` 分支；阶段验收通过后合并回 ```main```；每周五在 ```main``` 打 ```v1.4.0-rc.N``` 标签用于演练。
- **每个阶段三步**：先写半页以内的 design note（数据表变更、协议变更、兼容策略，放 ```docs/plans/design/```），再实现，最后跑验收并更新文档。
- **提交**：小步提交，message 说明「为什么」；不提交密钥、db、日志、out/、release/、target/。
- **Agent 协作**：一次只把一份 stage prompt 交给 agent；agent 完成后按报告格式回报，人工验收通过再进入下一阶段。
- **需要人拍板的决策点**（agent 遇到必须先停下询问）：
  - D1 在线文件目录布局与校验算法（建议 ```files/<yyyy-mm>/<sha256 前 2 位>/<sha256>```）。
  - D2 限额数值（建议图片 10 MiB、文件 128 MiB）。
  - D3 群权限矩阵细节（管理员能否踢管理员、能否转让群主）。
  - D4 群邀请是否需要对方同意（建议直接加入，简化）。
  - D5 更新检查频率与是否自动下载（建议启动静默检查 + 手动确认下载）。
  - D6 Android 版本映射规则（建议 ```1.4.0 → 0.4.0```，patch 跟随）。
  - D7 迁移窗口与回滚容忍（允许短时停机，迁移前备份 db）。

## 6. 阶段任务清单

### S0：基线（3 人日）

- **S0-1 Git 基线**：```git init```；写 ```.gitignore```（排除 ```target/```、```node_modules/```、```out/```、```release/```、```.tools/```、```*.key```、```*.db```、```*.log```、```replay_pid*.log```、service account JSON；保留 ```vendor/```）；提交前扫描敏感文件；首个提交打 tag ```baseline-2026-11-22```。
- **S0-2 单一版本源**：根 ```Cargo.toml``` 用 ```[workspace.package] version = "1.4.0"```；新增 ```scripts/sync-version.mjs``` 同步 ```apps/desktop/src-tauri/tauri.conf.json```、```frontend/package.json```、```android/app/build.gradle```（versionName 0.4.0 / versionCode 16）；扩展 ```scripts/check-version.mjs``` 校验一致；CI 调用。
- **S0-3 CI 补齐**：新增 Android 作业（ubuntu + JDK 17 + Android SDK 35 + NDK 30，```cargo build --target aarch64-linux-android``` + ```gradlew assembleDebug```，上传 APK artifact）；新增安装器作业（windows，```package-installer.ps1 -ValidateOnly```）；桌面作业加入 ```node scripts/p10-tls-acceptance.mjs```；加 ```actions/cache```（cargo registry/target、pnpm store）。
- **S0-4 基线体检**：记录当前测试通过率与已知失败（写入 [docs/testing.md](../testing.md)）；清理过期文案（[offline-messages.md](../offline-messages.md) 第 34 行、[administrator.md](../administrator.md) 的 Go 迁移期描述）。

### S1：发布与自更新（5 人日）

- **S1-1 发布工作流**：新增 ```.github/workflows/release.yml```；```v*``` tag 或手动触发；矩阵构建 LAN/Online 的 ZIP 与安装器；生成 ```SHA256SUMS```；创建 draft Release；Android APK 作为资产；Release 说明模板化。
- **S1-2 Tauri updater**：接入 ```tauri-plugin-updater```；生成 minisign 密钥对，公钥写进 ```tauri.conf.json```，私钥放 GitHub Secrets；两版独立通道（```latest-lan.json``` / ```latest-online.json```）；更新提示、下载进度、重启前确认；局域网版若正在开房，提示「重启会断开所有成员」。
- **S1-3 更新检查 UI**：设置页「检查更新」按钮；启动静默检查（失败静默）；显示当前版本与发布日期。
- **S1-4 latest.json 生成脚本**：```scripts/make-updater-manifest.mjs```，输入产物与签名，输出两版 manifest。
- **S1-5 发布文档**：更新 [release-runbook.md](../release-runbook.md)、[release-checklist.md](../release-checklist.md)、[github-publishing.md](../github-publishing.md)。

### S2：局域网权限持久化（5 人日）

- **S2-1 数据表**（```store.rs``` 的 LAN 库，用 ```PRAGMA user_version``` 迁移）：```lan_rooms(name, owner, private, password_hash, generation, created_at)```、```lan_room_members(room, user_code, allowed, updated_at)```、```lan_room_admins(room, user_code)```、```lan_room_mutes(room, user_code)```。
- **S2-2 启动加载**：```Hub``` 启动时从库重建 ```rooms```；```lobby``` 保持虚拟不落库；```generation``` 单调递增并持久化。
- **S2-3 写路径**：建房/踢人/删除/密码/管理员/禁言时同事务写库；内存只作运行态缓存，DB 为真源。
- **S2-4 安全语义不变**：连接批准**不落库**、重启后仍需房主逐次批准；白名单只决定「批准后能进哪个房间」。补一条测试断言防止回归。
- **S2-5 测试**：```lan/store.rs``` 单测；新增「同一 db 启动两次 Hub」集成测试；扩展 [server-rust/tests/lan_desktop.rs](../../server-rust/tests/lan_desktop.rs)。

### S3：在线存储重构（6 人日）

- **S3-1 存储抽象**：新模块 ```store::files```；数据目录 ```files/```；```online_files``` 增 ```path/hash/checksum```，文件内容不再进 BLOB。
- **S3-2 分块写盘**：写临时文件 → 校验长度与 SHA-256 → 原子 rename；读取按需分块；过期文件清理任务（用 ```expires```）。
- **S3-3 迁移命令**：```lan-chat-server --migrate-storage [--dry-run]```；迁移 ```online_file_chunks``` 与 ```chat_messages.online_image``` → 落盘 → 校验 → 置 NULL / 删表；迁移前 ```PRAGMA integrity_check``` 与 db 备份；幂等可重跑；逐条日志与总数统计。
- **S3-4 限额与能力**：图片 4 → 10 MiB、文件 32 → 128 MiB；capability 通告（如 ```online-files-v2```），旧客户端仍按 32 MiB 使用；协议文档同步。
- **S3-5 测试**：迁移夹具（造 BLOB 的测试库）覆盖 dry-run 与实跑；上传/下载/取消/过期清理；[protocol.md](../protocol.md) 更新。

### S4：在线群能力（8 人日）

- **S4-1 表结构**：```online_groups``` 增 ```owner, announcement, avatar, created_at```；```online_group_members``` 增 ```role, joined_at```；```PRAGMA user_version``` 迁移。
- **S4-2 命令与权限矩阵**：```group_invite / group_kick / group_role / group_transfer / group_update / group_announce```；角色 ```owner/admin/member```；每个命令定义「谁能对谁做」，写成表驱动测试。
- **S4-3 群文件与群图片**：复用 transfer 分块通道，收件方支持群；仅成员可上传/下载；消息带附件元数据，历史可分页拉取。
- **S4-4 客户端 UI**：群详情面板（成员列表、角色操作、公告编辑、群设置）、群文件列表、图片预览复用；权限不足时按钮置灰并提示原因。
- **S4-5 事件与推送**：群事件（邀请/踢人/角色/公告）广播 ```groups_changed```；群消息推送沿用 FCM，文案区分私信/群聊。
- **S4-6 测试**：权限矩阵单测；群文件 E2E；旧客户端收到未知命令时应忽略不崩溃。

### S5：Android、验收与发版（5 人日）

- **S5-1 Android 0.4.0**：接入单一版本源（versionName 0.4.0、versionCode 16）；修 FCM 登录与消息收发的稳定性问题；APK 随 Release 分发（本期不做应用内自动安装）。
- **S5-2 文档同步**：版本说明 ```docs/release-notes/v1.4.0.md```；[architecture.md](../architecture.md)、[protocol.md](../protocol.md)、[testing.md](../testing.md)、[release-acceptance.md](../release-acceptance.md)、[installer.md](../installer.md)、[unified-package.md](../unified-package.md)、[docs/README.md](../README.md)。
- **S5-3 验收**：虚拟机双机（发现、审批、断线重连、房间持久化跨重启）；Android 真机（在线群、群文件、推送）；测试服务器（部署、存储迁移演练、群权限走查）。
- **S5-4 发版**：走 ```release.yml``` 出 1.4.0 全部产物；核对 SHA256 与 manifest；发布说明；回滚预案（上一版安装包 + 数据备份）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 6 周排期偏紧 | 延期或质量下降 | 每周 rc 演练；砍线规则前置；S3/S4 允许跨周 |
| 仓库此前无 Git 历史 | 改坏无法回滚 | S0 先建基线并把 ```out/```、```release/``` 备份一份 |
| 存储迁移损坏数据 | 在线版文件丢失 | dry-run + 备份 + 校验 + 幂等；迁移窗口允许停机 |
| 协议变更破坏旧客户端 | 老用户连不上 | capability 通告；旧命令保持；新增命令未知时忽略 |
| 无代码签名证书 | SmartScreen 警告 | 接受并写进发布说明；updater 完整性签名不能省 |
| 局域网持久化改变安全语义 | 审批被绕过 | 审批不落库并加回归测试；白名单只影响房间准入 |
| SQLite 并发写冲突 | 在线服务报错 | WAL + busy_timeout + 单写事务；迁移期停写 |
| 群文件滥用 | 磁盘占满 | 每群配额 + 清理任务（D2 拍板数值） |
| Android CI 构建慢/NDK 漂移 | CI 超时 | 固定 NDK 版本、缓存、作业独立 |

## 9. 1.5 候选（本版不做）

- 局域网消息正文 E2EE（MLS group 扩展到消息体，保留旧消息 legacy 标记）。
- 设备信任免重复审批（公钥指纹 + 有效期）。
- 邀请码/二维码加入（含证书指纹）。
- 房主数据治理：一键备份/迁移、存储用量面板、FTS5 全文搜索。
- 在线私信 E2EE 可行性评估（先做落库加密）。
- 推送通道抽象（trait：FCM / 自建长连接 / 厂商通道 / relay）。
- 可观测性：健康检查、结构化日志、指标、审计。
- Android 应用内更新与 Play 上架；macOS/Linux 客户端。

## 10. 本轮决策记录（2026-11-22）

| 计划范围 | 两版各一个版本：LAN 1.4 + Online 1.4，含共同底座 |
