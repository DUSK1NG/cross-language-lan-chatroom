# LAN Chat 发布与局域网使用说明

LAN Chat 是一个面向可信局域网的 React + Qt WebEngine 桌面聊天室。同一份 Windows 运行包既可以创建本地聊天室，也可以加入其他房主的聊天室。

## 下载与安装

| 获取内容 | 适用场景 | 使用方式 |
| --- | --- | --- |
| `LANChat-Setup-x64.exe` | 所有普通用户（推荐） | 双击安装；自动创建开始菜单、可选桌面快捷方式与卸载项 |
| `LANChat-Windows-x64.zip` | 便携使用 | 解压后双击根目录的 `LANChat.exe` |

两个包都包含现代 GUI、Qt 运行时和本地 Go Server；都不包含初始证书、私钥、数据库、源码或编译工具。

## 房主：创建本地聊天室

1. 安装程序，或解压便携包并双击 `LANChat.exe`。
2. 选择“创建本地聊天室”，填写用户名和用户代码。
3. 点击“启动并连接”。程序会启动本机 Go Server，并在首次需要时自动创建 TLS 证书、私钥和数据库。
4. 保持房主程序运行。成员可在“附近聊天室”中发现并加入该房间。

新的房主身份和聊天数据库保存在当前 Windows 用户的：

```text
%LocalAppData%\DUSK1NG\LAN Chat\host\
```

其中包含 `certs\server-lan.crt`、`certs\server-lan.key` 和 `chat.db`。升级前版本已存在于安装目录 `server-go\` 下的数据会继续使用，不会被自动迁移或删除。

房主首次在本机启动时会自动成为管理员。其他电脑第一次加入后，房主会在聊天窗口右上角看到“设备审批”；请通过当面、电话或其他可信渠道核对对方身份后再点击“批准”。成员收到待审批提示后，待批准完成再次点击加入即可。

首次收到 Windows 防火墙提示时，只允许 `chat-server.exe` 通过“专用网络”。不要关闭整个防火墙，也不要把 TCP `8888` 映射到公网。

## 成员：加入局域网聊天室

1. 运行同一个 `LANChat.exe`，选择“加入局域网聊天室”。
2. 等待“附近聊天室”扫描，选择房主，填写自己的用户名和用户代码。
3. 首次加入未知房主前，通过当面、电话或其他可信渠道核对房主名称与页面中的证书指纹；勾选确认后再加入。客户端会为该房主创建一枚本机设备凭据。
4. 首次接入会等待房主审批设备。房主批准后再次点击加入；成功后，客户端会固定校验房主的公开证书。房主的 IPv4 日后变化时，自动发现会使用新地址重新连接。

如果附近聊天室没有房间，先刷新。访客网络、AP/Client Isolation、隔离 VLAN 或禁止 UDP 广播的网络不支持自动发现；此时选择“改用手动连接”，向房主取得真实 IPv4、端口 `8888` 和**公开**证书 `server-lan.crt`。跨电脑测试不能使用 `127.0.0.1`。

可在成员电脑运行：

```powershell
Test-NetConnection <房主IPv4> -Port 8888
```

## 卸载与本地数据

通过 Windows“设置 → 应用 → 已安装的应用”卸载 `LAN Chat`，或运行安装目录的 `unins000.exe`。卸载器移除程序、快捷方式和卸载项，但不会删除 `%LocalAppData%\DUSK1NG\LAN Chat\host\` 中的私钥、数据库和聊天记录。

如需彻底清除房主身份，请先确认不再需要历史数据，再手动删除该 `host` 目录；删除后成员需重新核对新生成的证书指纹。

## 安全边界

LAN Chat 适用于彼此信任的局域网。TLS 加密并校验证书，但不是端到端加密，房主服务端能读取并保存聊天内容。用户名与用户代码不是登录密码；每台新设备必须经房主审批，其本机设备凭据使用 Windows DPAPI 加密保存，而服务端仅保留不可逆摘要。该机制不能替代公网账户系统或端到端加密。

自动发现基于 UDP 广播，附近设备可能伪造公告；因此首次加入前必须通过可信渠道核对指纹。`server-lan.key`、`chat.db`、聊天记录和访问令牌只应留在房主的本地受保护目录，不能发送给成员、放入同步盘或提交到 GitHub。
